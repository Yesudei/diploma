\chapter{Туршилт ба үр дүн}
\label{Chapter4}

\section{Бүлгийн зорилго}
Энэ бүлэгт хөгжүүлсэн платформын үндсэн ажиллагааг туршсан арга, локал demo орчин, хэрэглэгчийн урсгалын шалгалт, чатботын хариу, өгөгдлийн багцын баталгаажуулалт болон гарсан үр дүнг нэгтгэнэ. Туршилтын зорилго нь бүх production шаардлагыг бүрэн батлах бус, дипломын MVP түвшинд платформын гол функцууд хоорондоо уялдан ажиллаж байгааг нотлох явдал юм.

Туршилтаар дараах хэсгүүдийг шалгав.
\begin{itemize}
  \item нүүр хуудас, курсийн каталог, курсийн дэлгэрэнгүй, хичээлийн тоглуулагч;
  \item үнэгүй болон төлбөртэй хичээл ялгарах байдал;
  \item хяналтын самбар, төлбөрийн хуудас, админ чиглэлийн урсгал;
  \item \texttt{/api/ai-chat} зам болон Studio mentor чатботын UI;
  \item Qdrant-д хадгалсан RAG өгөгдлийн багцын бүтэц, хэмжээ, эх сурвалжийн мета өгөгдөл;
  \item локал хөгжүүлэлтийн тохиргооны давтагдах боломж.
\end{itemize}

\section{Туршилтын орчин}
Платформыг гэрийн компьютер дээр локал хөгжүүлэлтийн хэлбэрээр ажиллуулж шалгасан. Фронтенд талд Next.js хөгжүүлэлтийн сервер ажиллаж, хөтчөөр \texttt{http://localhost:3000} хаягаар хандсан. Studio mentor чатбот нь browser-оос зөвхөн \texttt{/api/ai-chat} замыг дуудаж, сервер талд Ollama болон Qdrant-тэй харилцана. Ингэснээр төлбөртэй API эсвэл үүлэн үйлчилгээ ашиглахгүйгээр RAG хариулт үүсгэх боломжтой болсон.

\section{Чатботын туршилт}
Чатботын фронтенд нь \texttt{/chat} зам дээр байрлаж, хэрэглэгчийн асуултыг \texttt{/api/ai-chat} руу илгээдэг. API зам нь зурвас шалгах, Монгол кирилл болон латин бичлэгийг normalization хийх, Ollama \texttt{bge-m3} embedding үүсгэх, Qdrant collection-оос top 5 chunk хайх, grounded prompt бүрдүүлэх, Ollama \texttt{qwen3:8b} загвараар хариу үүсгэх гэсэн дарааллаар ажиллана. Туршилтад \textit{``kick bolon 808 hoorondoo murulduud bn yaj zasah ve?''} гэсэн beginner production асуулт ашигласан.

\section{Өгөгдлийн багцын үр дүн}

\section{Хязгаарлалт}
Одоогийн туршилт нь дипломын MVP түвшний баталгаажуулалт юм. Production орчинд дараах хязгаарлалтыг заавал сайжруулах шаардлагатай.
\begin{itemize}
  \item курсийн өгөгдөл static seed болон Supabase table хоёрт зэрэг байрлаж байгаа тул нэг үндсэн эх сурвалжтай болгох;
  \item төлбөрийн урсгал simulation түвшинд байгаа тул бодит gateway, webhook, receipt validation нэмэх;
  \item RAG retrieval нь semantic search болсон боловч ranking evaluation, hybrid search, regression test нэмэх;
  \item generated өгөгдөл их тул албан болон багшийн баталгаажуулсан citation-safe эх сурвалж нэмэх;
  \item automated end-to-end test, security policy test, load test нэмэх;
  \item локал Ollama болон Qdrant service ажиллахгүй үед чатбот clean error буцаах боловч хариу үүсгэх боломжгүй.
\end{itemize}

\section{Бүлгийн дүгнэлт}
Дөрөвдүгээр бүлгээр платформын гол ажиллагааг локал орчинд шалгаж, нүүр хуудас, курсийн каталог, хичээлийн дэлгэрэнгүй, Studio mentor чатботын хариу, Qdrant RAG өгөгдлийн багцын үр дүнг баримтжууллаа. Туршилтаас харахад платформ нь FL Studio болон хөгжим боловсруулалт суралцагчдад зориулсан сургалтын үндсэн урсгалыг харуулж чадаж байна: хэрэглэгч курс сонгох, хичээл үзэх, төлбөртэй хандалтын ялгаа харах, RAG туслахаас эх сурвалжтай зөвлөгөө авах боломжтой.

Үр дүнгийн хувьд фронтенд MVP, Supabase schema, локал Ollama/Qdrant RAG, \texttt{/api/ai-chat} API, өгөгдөл үүсгэх болон ingestion script, studio-style UI refresh бүрдсэн. Хяналтын самбар нь тусдаа studio-console layout болж, зүүн navigation, төв сургалтын workspace, баруун профайл/ахиц/ментор rail гэсэн бүтэцтэй болсон. Харин production түвшинд хүргэхийн тулд өгөгдлийн багцын эх сурвалжийн чанар, retrieval evaluation, payment integration, automated testing болон admin CRUD-г дараагийн хөгжүүлэлтийн гол чиглэл болгох шаардлагатай.
