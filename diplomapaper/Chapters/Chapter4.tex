\chapter{Туршилт ба үр дүн}

\section{Бүлгийн зорилго}
Энэ бүлэгт хөгжүүлсэн платформын үндсэн ажиллагааг туршсан арга, локал demo орчин, хэрэглэгчийн урсгалын шалгалт, чатботын хариу, өгөгдлийн багцын баталгаажуулалт болон гарсан үр дүнг нэгтгэнэ. Туршилтын зорилго нь бүх production шаардлагыг бүрэн батлах бус, дипломын MVP түвшинд платформын гол функцууд хоорондоо уялдан ажиллаж байгааг нотлох явдал юм.

Туршилтаар дараах хэсгүүдийг шалгав.
\begin{itemize}
  \item нүүр хуудас, курсийн каталог, курсийн дэлгэрэнгүй, хичээлийн тоглуулагч;
  \item үнэгүй болон төлбөртэй хичээл ялгарах байдал;
  \item хяналтын самбар, төлбөрийн хуудас, админ чиглэлийн урсгал;
  \item \texttt{/api/chat} зам болон чатботын UI;
  \item RAG өгөгдлийн багцын бүтэц, хэмжээ, эх сурвалжийн мета өгөгдөл;
  \item локал хөгжүүлэлтийн тохиргооны давтагдах боломж.
\end{itemize}

AI чатбот нь локал JSONL өгөгдлийн багц уншиж, \texttt{CHAT\_PROVIDER} тохиргооноос хамааран Ollama, Gemini эсвэл OpenAI-compatible үйлчилгээ үзүүлэгч ашиглах боломжтой.

\section{Чатботын туршилт}
Чатботын фронтенд нь \texttt{/chat} зам дээр байрлаж, хэрэглэгчийн асуултыг \texttt{/api/chat} руу илгээдэг. API зам нь зурвас шалгах, RAG сэргээн хайлт хийх, зааварчилгаа бүрдүүлэх, үйлчилгээ үзүүлэгчийн хийсвэрлэл, нөөц хариуны логик гэсэн дарааллаар ажиллана. Туршилтад limiter-ийн dynamic range алдагдах тухай асуулт ашигласан.

\section{Хязгаарлалт}
Одоогийн туршилт нь дипломын MVP түвшний баталгаажуулалт юм. Production орчинд дараах хязгаарлалтыг заавал сайжруулах шаардлагатай.
\begin{itemize}
  \item курсийн өгөгдөл static seed болон Supabase table хоёрт зэрэг байрлаж байгаа тул нэг үндсэн эх сурвалжтай болгох;
  \item төлбөрийн урсгал simulation түвшинд байгаа тул бодит gateway, webhook, receipt validation нэмэх;
  \item RAG retrieval нь lexical scoring ашиглаж байгаа тул semantic search буюу embedding/pgvector нэмэх;
  \item citation-safe өгөгдлийн бичлэг цөөн тул албан болон багшийн баталгаажуулсан эх сурвалж нэмэх;
  \item automated end-to-end test, security policy test, load test нэмэх;
  \item локал LLM үйлчилгээ үзүүлэгч ажиллахгүй үед нөөц хариу ажиллах боловч бүх асуултад бүрэн хангалттай биш.
\end{itemize}

\section{Бүлгийн дүгнэлт}
Дөрөвдүгээр бүлгээр платформын гол ажиллагааг локал орчинд шалгаж, нүүр хуудас, курсийн каталог, хичээлийн дэлгэрэнгүй, чатботын хариу, өгөгдлийн багцын тайлан зэрэг үр дүнг баримтжууллаа. Туршилтаас харахад платформ нь FL Studio болон хөгжим боловсруулалт суралцагчдад зориулсан сургалтын үндсэн урсгалыг харуулж чадаж байна: хэрэглэгч курс сонгох, хичээл үзэх, төлбөртэй хандалтын ялгаа харах, AI туслахаас зөвлөгөө авах боломжтой.

Үр дүнгийн хувьд фронтенд MVP, Supabase schema, RAG өгөгдлийн багц, chat API, локал тохиргоо бүрдсэн. Харин production түвшинд хүргэхийн тулд өгөгдлийн багцын эх сурвалжийн чанар, semantic retrieval, payment integration, automated testing болон admin CRUD-г дараагийн хөгжүүлэлтийн гол чиглэл болгох шаардлагатай.
